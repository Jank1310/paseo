# Runin plugin for released Paseo

## Approved behavior

On 2026-10-02 the user accepted manual SSH connection so the plugin can run in
the normal Homebrew Paseo application. The Runin sidebar creates a persistent
Machine from the versioned Template and starts its daemon. The completed job
shows a selectable SSH URI and instructions for Hosts → Add host → Remote SSH.
No automatic registration or addition to the connection-method menu is required.

The Template includes Node, Python 3, Go, Bun, Docker Engine with Compose and
Buildx, Paseo, Codex, Claude Code, Pi, official Grok Build, and GitHub CLI.
Agent credentials remain user-configured. The daemon service stays disabled in
the image and starts on each cloned Machine so identities are not copied.

## Implementation

- [x] Remove the custom connectSshHost and server.pluginId APIs from Paseo core.
- [x] Replace automatic connection with a selectable URI and manual instructions.
- [x] Guard a shared recovery journal using only the released plugin server API.
- [x] Verify and install into the normal Paseo app without replacing its binaries.
- [x] Put existing Machines first with live status dots, resource details, and selectable SSH addresses.
- [x] Include GitHub CLI in the Template and install it on both existing plugin Machines.

## Recovery constraints

Persist before submitting Machine creation and retain the unique request name.
Never repeat an ambiguous creation; reconcile by that name. Setup retry reuses
the saved Machine ID. Background jobs continue after the screen closes. Keep
SSH credentials on the managing daemon and disable agent forwarding.
